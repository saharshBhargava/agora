## Q1. What is in Visa's agentic-commerce stack (Intelligent Commerce, Trusted Agent Protocol, agentic tokens, Acceptance Agent Toolkit / MCP server, Developer sandbox), and what can a student team actually hit in 24–36 hours?

### Takeaway
As of mid-October 2025 Visa had four distinct pieces: (1) Visa Intelligent Commerce (announced Apr 30, 2025; APIs described as "live" with a free sandbox but production/pilot access gated through Visa), (2) Visa Acceptance Agent Toolkit + Visa MCP Server (Sep 4, 2025, explicitly "pilot," npm-installable, but needs a Visa Acceptance/Cybersource merchant ID, REST shared-secret key, and Invoicing/Pay-by-Link enabled by an account manager), (3) Trusted Agent Protocol (Oct 14, 2025, public spec + open sample code on GitHub, fully runnable locally with no credentials), and (4) the general Visa Developer sandbox. The most realistically hackable pieces in a weekend are TAP's open-source sample stack (self-contained, Python/Node) and the Cybersource/Visa Acceptance sandbox (self-serve test key), while Intelligent Commerce token provisioning requires a token requester ID from a Visa account manager and is therefore effectively announcement/pilot-only for students.

### Cited Findings

**Visa Intelligent Commerce (VIC) — announced Apr 30, 2025 [as of Oct 2025]**
- Announced Wednesday April 30, 2025 at Visa's Global Product Drop in San Francisco; described as opening Visa's payment infrastructure to developers, engineers and AI platforms building agents that search, recommend and pay. — [PYMNTS, Apr 30 2025](https://www.pymnts.com/visa/2025/visa-powers-ai-shopping-agents-with-intelligent-commerce-payment-rails); [Retail Insider](https://retail-insider.com/retail-insider/2025/04/visa-unveils-intelligent-commerce-platform-to-power-ai-payments/)
- Five launch modules: **Authentication** (confirms the agent is authorized to act for a specific consumer), **Tokenization** (replaces card data with network tokens usable wherever Visa is accepted), **Payment Instructions** (users preset dollar limits, merchant categories, or real-time approval prompts), **Personalization** (with consent, shares basic spend patterns so the agent can rank offers), **Signals** (streams transaction signals back to Visa in real time for risk controls and dispute resolution). — [PYMNTS](https://www.pymnts.com/visa/2025/visa-powers-ai-shopping-agents-with-intelligent-commerce-payment-rails)
- "AI-ready cards" / agentic tokens: the user uploads an existing Visa credential; Visa authenticates the cardholder with payment passkeys, tokenizes the card number, and places the token inside the AI agent so card details are not re-entered at each site. — [PYMNTS](https://www.pymnts.com/visa/2025/visa-powers-ai-shopping-agents-with-intelligent-commerce-payment-rails)
- Partners named with "live APIs" in launch coverage: Anthropic, OpenAI, Microsoft, Samsung, Stripe; developers "can start building now through a bundle of Visa APIs," with pilots "expected to surface in the coming months." — [PYMNTS](https://www.pymnts.com/visa/2025/visa-powers-ai-shopping-agents-with-intelligent-commerce-payment-rails)
- VGS announced Apr 30, 2025 it would be a preferred pilot partner for VIC. — [VGS press release](https://www.verygoodsecurity.com/press-releases/vgs-expands-partnership-with-visa-to-pioneer-ai-driven-commerce)
- Visa Developer's VIC capability page (per search-result summary; the page itself returned HTTP 403 to automated fetch) says VIC is free to use in the sandbox with production fees handled by contacting Visa; it provisions and manages agent-specific payment tokens; integrated services include token lifecycle APIs, cardholder step-up verification, passkey management, and an MCP Server; and it notes the product "is in the process of development and deployment and may not be available in all markets." — [developer.visa.com VIC overview](https://developer.visa.com/capabilities/visa-intelligent-commerce/overview) (not directly verified; 403)
- The Visa Acceptance Platform (Cybersource) "Intelligent Commerce" developer guide documents concrete REST endpoints: `POST /acp/v1/tokens` (enroll a card, with optional consent-data fields), `POST /acp/v1/instructions` (initiate a purchase intent, with payment-mandate fields such as decline threshold, expiry, description; returns an instruction ID), `PUT /acp/v1/instructions/{id}` and `.../cancel`, `POST .../credentials` (retrieve tokenized card for the chosen purchase option), `POST .../confirmations` (returns `COMPLETED`), plus Passkey Service / step-up TMS endpoints (OTP, issuer-code validation, passkey-backed credentials), `/tms/v1/instrumentidentifiers`, and push provisioning. — [Visa Acceptance Intelligent Commerce developer guide](https://developer.visaacceptance.com/docs/vas/en-us/intelligent-commerce/developer/all/rest/intelligent-commerce.html)
- Sandbox prerequisites for that guide: sign up for a sandbox account (creates a test REST shared secret key); have a merchant ID or organization ID; **obtain a token requester ID and relationship ID from your Visa Acceptance Platform account manager**; set up Passkey Service and TMS including message-level-encryption (MLE) keys (separate for test/prod, expire after 3 years). Passkey Service, push provisioning and card art are flagged "This feature is in the pilot phase" and "may contain bugs." — [same guide](https://developer.visaacceptance.com/docs/vas/en-us/intelligent-commerce/developer/all/rest/intelligent-commerce.html)

**Visa MCP Server and Visa Acceptance Agent Toolkit — Sep 4, 2025 [as of Oct 2025]**
- Dated 09/04/2025. The Visa MCP Server is "a secure integration layer" letting agents/LLMs connect to Visa Intelligent Commerce APIs via Model Context Protocol, "designed to extend across Visa's broader API portfolio over time." The Acceptance Agent Toolkit is built on the MCP Server, offers prebuilt workflows for Acceptance Invoicing and Pay By Link, ships as a self-hosted npm package for JavaScript developers, enforces policies and role-based access controls, and lets non-technical users trigger actions "without writing a single line of code." **Both are in pilot.** Access: contact your Visa representative or visit the Visa Acceptance Developer Center to request Toolkit access. — [Visa Perspectives, Sep 4 2025](https://corporate.visa.com/en/sites/visa-perspectives/innovation/visa-mcp-server-agent-acceptance-toolkit.html)
- Toolkit docs: TypeScript toolkit for Pay by Link and Invoicing APIs; "pilot phase"; requirements are Node.js 18+, a Visa Acceptance Solutions merchant ID (MID) or org ID, a REST API shared secret key (sandbox sign-up creates a test key), and Invoicing or Pay by Link APIs enabled "which requires contacting your account manager." Works with Vercel AI SDK, as an MCP server, and in IDE tools such as Claude Desktop. Source repo: github.com/visaacceptance/agent-toolkit. — [Visa Acceptance Agent Toolkit intro](https://developer.visaacceptance.com/docs/vas/en-us/agent-toolkit/quick-start/all/na/agent-toolkit/agent-toolkit-intro.html)
- npm package is `@visaacceptance/mcp`, run via `npx` with merchant credentials; documented commands point to the test environment by default. — [Cybersource agent-toolkit quick start](https://developer.cybersource.com/docs/vas/en-us/agent-toolkit/quick-start/all/na/agent-toolkit.html) (from search summary)
- Visa says it does not supply any LLMs with the MCP server; a third-party MIT-licensed mirror exists at github.com/fastmcp-me/agent-toolkit (unofficial). — [Glama listing](https://glama.ai/mcp/servers/qnhj7qw4oa)

**Visa Trusted Agent Protocol (TAP) — Oct 14, 2025 [as of Oct 2025]**
- Unveiled Oct 14, 2025 in San Francisco, developed with Cloudflare; "available now through the Visa Developer Center and on GitHub"; the release says initial specifications apply to the Visa network "in this phase." — [Visa investor press release](https://investor.visa.com/news/news-details/2025/Visa-Introduces-Trusted-Agent-Protocol-An-Ecosystem-Led-Framework-for-AI-Commerce/default.aspx); also at [usa.visa.com newsroom](https://usa.visa.com/about-visa/newsroom/press-releases.releaseId.21716.html)
- Motivation: AI-driven traffic to U.S. retail sites up >4,700% in the past year (Visa's figure); merchants face bot-detection blocking legitimate agents, supporting agent guest/logged-in checkout, and keeping visibility into the consumer and payment data behind the agent. — [Visa press release](https://investor.visa.com/news/news-details/2025/Visa-Introduces-Trusted-Agent-Protocol-An-Ecosystem-Led-Framework-for-AI-Commerce/default.aspx)
- Three information categories carried by agent-specific cryptographic signatures: **Agent Intent** (trusted agent intends to research or buy), **Consumer Recognition** (whether the consumer has an existing account/prior interaction with the merchant), **Payment Information** (optional payment data to support the merchant's checkout). Built on the HTTP Message Signature standard, aligned with Web Bot Auth (IETF), intended to align with IETF, OpenID Foundation, EMVCo, to work with the Agentic Commerce Protocol, and to interoperate with Coinbase's x402. Early feedback partners: Adyen, Ant International, Checkout.com, Coinbase, CyberSource, Elavon, Fiserv, Microsoft, Nuvei, Shopify, Stripe, Worldpay. — [Visa press release](https://investor.visa.com/news/news-details/2025/Visa-Introduces-Trusted-Agent-Protocol-An-Ecosystem-Led-Framework-for-AI-Commerce/default.aspx)
- Cloudflare's parallel release (Oct 14, 2025): TAP "enables payment networks to integrate Web Bot Auth"; Mastercard is incorporating Web Bot Auth into Agent Pay and American Express into its agentic program; agents built with Cloudflare Agents SDK "will soon be able to use these protocols" (i.e., not yet). Cloudflare also contributed to Google AP2, introduced NET Dollar, and is establishing the x402 Foundation with Coinbase. — [Cloudflare press release](https://www.cloudflare.com/press/press-releases/2025/cloudflare-collaborates-with-leading-payments-companies-to-secure-and-enable-agentic-commerce/)
- Visa Developer TAP "Getting started" page: "Available for use by: Merchants, Independent developers." Describes two resources: the protocol document (RFC 9421 cryptographic standard, required message-signature fields, process for validating agent intent) and sample code showing public keys and how to construct `signature_base` strings. The merchant's task is to reconstruct `signature_base` from request attributes and verify with the agent's public key; the protocol also describes signatures for consumer recognition and payment. Sidebar sections: Getting started, Merchant specifications, Product terms. — [developer.visa.com TAP getting started](https://developer.visa.com/capabilities/trusted-agent-protocol); merchant spec at [trusted-agent-protocol-specifications](https://developer.visa.com/docs/trusted-agent-protocol/trusted-agent-protocol-specifications)
- GitHub repo `visa/trusted-agent-protocol` README: a **sample implementation** with five components — TAP Agent (Python/Streamlit, generates signatures), Merchant Frontend (React), Merchant Backend (FastAPI, verifies signatures), CDN Proxy (Node.js, verifies signatures), Agent Registry (Python public-key registry). Signatures are RFC 9421 compliant, bound to merchant domain and operation (browsing vs payment), include timestamps, session identifier, key identifier, algorithm identifier (anti-relay/replay). Consumer/payment data (verifiable consumer identifiers, Payment Account References (PARs), loyalty numbers, emails, phones) are shared only with consumer consent and passed as query parameters. Runs entirely on localhost ports (registry 8001, backend 8000, CDN proxy 3002, frontend 3001, agent 8501). License, version and how a real agent gets Visa-approved keys are **not stated** in the README. — [visa/trusted-agent-protocol README](https://github.com/visa/trusted-agent-protocol)

**Later developments [post-Oct-2025], for context only**
- Visa launched "Intelligent Commerce Connect," a single integration for merchants, agent builders and payment enablers; in pilot with a small group of partners. — [TechInformed](https://techinformed.com/visa-opens-one-integration-for-ai-agent-payments/)
- Visa reported 30+ projects in the VIC sandbox as of Dec 2025 (secondhand). — [eco.com explainer](https://eco.com/support/en/articles/14845484-visa-intelligent-commerce-explained)

### Inferences
- **Hackable in 24–36 h with zero gatekeeping:** the TAP sample stack (clone, run agent + registry + merchant + CDN proxy locally; swap in your own agent that signs requests per RFC 9421). It demonstrates the exact "trusted agent vs bot" story Visa is telling in Oct 2025.
- **Hackable with self-serve sandbox signup:** Cybersource / Visa Acceptance sandbox (standard payments, tokenization via TMS, Pay by Link, Invoicing) — sandbox signup gives a test key immediately; but the **Agent Toolkit / MCP server additionally needs Invoicing or Pay-by-Link enabled by an account manager**, which a student likely cannot obtain in a weekend unless Visa staff at the event pre-provision it.
- **Announcement / pilot only for students:** VIC agent token provisioning and Payment Instructions (mandates) — requires token requester ID + relationship ID from a Visa account manager, MLE keys, and pilot-phase passkey service. A team should mock these or build the *shape* of these flows (mandate object, spend ceilings, step-up) in their own backend.
- Notably, the DH25 Visa challenge itself (Q3) explicitly allowed "any open-source or publicly available payment API (e.g., Stripe, PayPal Sandbox, Square, Razorpay, or mock payment libraries)," implying Visa did not expect teams to hit Visa's own gated APIs.

### Gaps
- Could not fetch developer.visa.com VIC overview directly (HTTP 403); its API list is from a search-engine summary. Exact Visa Developer VIC API names/endpoints and whether the VIC MCP server is downloadable without a Visa rep were not confirmed.
- TAP repo license, spec version number, and the real-world agent onboarding process (how an agent becomes "Visa-approved" and gets listed in the key directory) are not documented in the README retrieved.
- No evidence found of a public agent-registration API or a public "approved agents" directory endpoint as of Oct 2025.

## Q2. What spend-control, mandate, consent, and merchant-verification primitives does Visa's stack expose (relevant to a "Trust & Responsibility" criterion)?

### Takeaway
Visa's publicly described trust primitives are: (a) **Payment Instructions / mandates** — user-preset dollar ceilings, merchant-category limits, real-time approval prompts, and in the Cybersource ACP API a `decline threshold`, `expiry` and `description` on each purchase intent; (b) **cardholder authentication** via payment passkeys and step-up (OTP, issuer code, SMS/email/banking-app); (c) **network tokenization** so the agent never holds the PAN; (d) **consent fields** at card enrollment and consent-gated sharing of consumer identifiers in TAP; (e) **merchant-side agent verification** via TAP signatures bound to domain, operation, time and session; and (f) **transaction Signals** streamed back for risk and disputes. Most are described conceptually; the only ones with public machine-readable detail are the Cybersource ACP endpoints and the TAP signature spec.

### Cited Findings
- Payment Instructions: users preset dollar limits, merchant categories, or real-time approval prompts; example of a $500 ceiling on a hotel or airline ticket; the agent's token is constrained by these limits; Visa "verifies your instruction," loads it into VisaNet, then routes to the issuer for approval. Users can require the agent to ask approval above a set amount or pause before buying from unfamiliar sellers; users choose whether to share spend behavior for personalization. — [PYMNTS](https://www.pymnts.com/visa/2025/visa-powers-ai-shopping-agents-with-intelligent-commerce-payment-rails)
- Authentication module confirms the agent is authorized to act for a specific consumer; cardholder authenticated with payment passkeys before tokenization. — [PYMNTS](https://www.pymnts.com/visa/2025/visa-powers-ai-shopping-agents-with-intelligent-commerce-payment-rails)
- Visa FAQ (Sep 2025) describes VIC as equipping agents with "trusted payment rails, controls, and post-purchase support, including tokenization, authentication, and spending controls"; the Agent Toolkit enforces "policies and role-based access controls." — [Visa Perspectives](https://corporate.visa.com/en/sites/visa-perspectives/innovation/visa-mcp-server-agent-acceptance-toolkit.html)
- Cybersource ACP API: purchase intent (`POST /acp/v1/instructions`) carries payment-mandate fields — decline threshold, expiry, description; card enrollment (`POST /acp/v1/tokens`) has optional consent-data fields; credentials are retrievable only after enrollment and selection of a purchase-intent option; step-up options include SMS, email, online banking, app-to-app, customer service, outbound call; unmasked payment data requires message-level encryption. — [Visa Acceptance guide](https://developer.visaacceptance.com/docs/vas/en-us/intelligent-commerce/developer/all/rest/intelligent-commerce.html)
- TAP merchant verification: check signature timestamps are current (reject relayed/replayed requests), confirm signature matches the domain and page accessed; signatures distinguish browsing vs payment operations; consumer identifiers/PAR/loyalty/email/phone shared only with consumer consent. — [visa/trusted-agent-protocol](https://github.com/visa/trusted-agent-protocol); [Visa press release](https://investor.visa.com/news/news-details/2025/Visa-Introduces-Trusted-Agent-Protocol-An-Ecosystem-Led-Framework-for-AI-Commerce/default.aspx)
- Signals module streams transaction signals to Visa in real time for risk controls and dispute resolution. — [PYMNTS](https://www.pymnts.com/visa/2025/visa-powers-ai-shopping-agents-with-intelligent-commerce-payment-rails)
- Visa Developer also lists a separate "Visa Consent Management Service" product in the same docs navigation as TAP (name only; not researched further). — [developer.visa.com TAP page sidebar](https://developer.visa.com/capabilities/trusted-agent-protocol)

### Inferences
- A hackathon project can credibly model Visa's trust vocabulary without gated access: an explicit **mandate object** (ceiling, category allowlist, expiry, "ask me above $X," "pause on unfamiliar merchant"), **step-up** before provisioning, **tokens scoped per agent**, and a **signed-request audit log** (TAP-style) — all of which map one-to-one onto Visa's stated modules and would read well to Visa judges.
- Because Visa's own Payment Instructions are enforced "in VisaNet," a demo can honestly say "in production this is enforced at the network; in our prototype it is enforced in our policy layer."

### Gaps
- No public schema was found for Visa Developer's (non-Cybersource) Payment Instructions/mandate object or for merchant-category controls; the PYMNTS description is narrative.
- Liability rules for agent-initiated Visa transactions (who eats fraud when a mandate is violated) were not found in primary Visa sources.

## Q3. What did the DubHacks '25 Visa challenge actually say, how was it judged, and what did Visa reward?

### Takeaway
The DubHacks '25 Visa prize was titled **"VISA – Play, Pay, Repeat: Reinventing Childhood Joy with Modern Payments"** (one winner, iPads for all team members), asking teams to reimagine childhood experiences (allowance, trading cards, arcade games) with Visa's payment network; it explicitly allowed any public payment API or mock library and required gamification, security/inclusivity (parental controls, fraud prevention) and a working demo. The published DubHacks-wide Devpost judging criteria were Functionality 30%, Design 10%, Creativity 20%, Track Applicability 20% (8 points each; detailed rubric in the Hacker Guide). The winner was "Minty," a gamified tooth-fairy/dental-hygiene app where the tooth fairy pays the child via Visa. **The Innovation/UX/Technical/Commerce Impact/Trust & Responsibility weighting in the assignment was not found anywhere.**

## Q5. Perceptron: models, modalities, access, pricing, latency, strengths, and limitations for inventory-style item recognition from a phone video walkthrough

### Takeaway
As of Oct 17, 2025 Perceptron's only released model was **Isaac 0.1** (Sep 17, 2025): a 2B-parameter open-weight (CC-BY-NC-4.0 weights, Apache-2.0 code) image+text→text model fine-tuned from Qwen3-1.7B, strong at grounded pointing/localization, OCR in dense scenes, counting, and few-shot in-context visual learning, runnable via Transformers/vLLM/SGLang/`pip install perceptron`, hosted on fal.ai ($0.26/M in, $2.17/M out) and Replicate. **It is image-only; video is not a documented input**, so a phone walkthrough would have to be frame-sampled client-side. Native video (tracking, temporal grounding at up to 2 FPS, 32K context) only arrived with the closed-source Mk1 in May 2026 and Mk1.5 later — post-cutoff.

### Cited Findings

**Isaac 0.1 [as of Oct 2025]**
- Published Sep 17, 2025; "open-source, 2B-parameter model"; capabilities: precise pointing and region localization, reading small text/dense scenes across resolutions, in-context learning of new categories from a few annotated examples without fine-tuning, "Conversational Pointing" (visual citations), visual QA and spatial reasoning; evaluated on counting benchmarks (Pixmo Counting, CVBench, CountBench). Video is not mentioned. Qualitative efficiency claims only ("edge-ready tail latencies," "drastically lower serving cost"); no latency numbers. Team described as behind Meta's Chameleon models; existing enterprise work in manufacturing, logistics, security. — [Perceptron blog: Introducing Isaac 0.1](https://www.perceptron.inc/blog/introducing-isaac-0-1)
- Benchmarks (Perceptron's own table): VQA v2 82.12% (vs 77.13% Gemini 2.5 Flash Lite); DocVQA 91.22% (vs 94.22% Gemini 2.5 Flash); RealWorldQA 74.87% (vs 79.58% Flash); CountBench 86.68% (vs 88.11% GPT-4o); RefCOCO 77.15% (vs 75.79% Flash); Perceptron-Grounding-ICL 68.50% (vs 30.57% GPT-4o). Isaac trails on several rows despite the "matches or exceeds" headline; some benchmarks are internal. — [Perceptron blog](https://www.perceptron.inc/blog/introducing-isaac-0-1)
- Hugging Face model card: pipeline tag `image-text-to-text`; fine-tuned from Qwen/Qwen3-1.7B; license cc-by-nc-4.0; metadata says 3B params (F32) while text says 2B (inconsistent); run via Transformers (`trust_remote_code=True`, needs `IsaacProcessor` from the GitHub repo), `pip install perceptron`, vLLM (`vllm serve`, OpenAI-compatible on :8000), SGLang, Docker Model Runner; playground at perceptron.inc/demo; no limitations section; "dynamic image handling" across resolutions; context length not stated; video not mentioned. — [HF PerceptronAI/Isaac-0.1](https://huggingface.co/PerceptronAI/Isaac-0.1)
- Code license Apache 2.0, weights CC-BY-NC-4.0 (non-commercial). — [Replicate readme](https://replicate.com/perceptron-ai-inc/isaac-0.1/readme); [HF](https://huggingface.co/PerceptronAI/Isaac-0.1)
- Hosted on fal.ai as an OpenAI-compatible chat endpoint `https://fal.run/perceptron/isaac-01/openai/v1/chat/completions`; pricing $0.26 per 1M input tokens, $2.17 per 1M output tokens; no latency/limits/schema published. — [fal.ai Isaac-01](https://fal.ai/models/perceptron/isaac-01/openai/v1/chat/completions/llms.txt); [fal blog](https://blog.fal.ai/isaac-the-first-perceptive-language-model-on-fal/)
- Replicate's blog post about Isaac 0.1 is dated Nov 26, 2025 (Replicate's hosting date, not the model release date). — [Replicate blog](https://replicate.com/blog/isaac-01)
- Voxel51 (FiftyOne) has an Isaac 0.1 plugin. — [Voxel51 plugin page](https://docs.voxel51.com/plugins/plugins_ecosystem/isaac0_1.html)

**Company / later models [post-Oct-2025]**
- Perceptron homepage describes "a model layer for physical AI"; offers Isaac 0.1 and 0.2, Perceptron Mk1 and Mk1.5 ("New"), a "Perceptron Egocentric API," API access or commercial weight licenses, a platform login and demo; target verticals include sports, infrastructure, aerial, smart home, manufacturing, personal agents, wearables, security, agriculture. — [perceptron.inc](https://www.perceptron.inc)
- Mk1 (May 12, 2026): first closed-source model; video understanding and embodied reasoning; temporal grounding at up to 2 FPS with 32K-token context, returns timecodes; object tracking through occlusion; "counting is reliable into the hundreds in dense scenes"; in-context matching from a reference image/video; structured outputs (points, boxes, polygons, tracks, clips); $0.15/M input, $1.50/M output; model ID `perceptron-mk1`; claims parity with Gemini Pro-class models on video at lower cost than Gemini Flash Lite; "surpasses the open-source Isaac series across the board." — [Perceptron blog: Introducing Mk1](https://www.perceptron.inc/blog/introducing-perceptron-mk1)
- Mk1.5 docs: model ID `perceptron-mk1.5`; endpoint `https://api.perceptron.inc/v1/chat/completions`, Bearer `PERCEPTRON_API_KEY`; Python SDK `pip install "perceptron>=0.4.0"`; image, video and audio inputs; context 36,864 tokens, max output 8,192; pricing $0.15 / $1.50 / $0.0375 cached per 1M; `annotation_format` values `point`, `box`, `polygon`, `clip`, with `track` as a markup container; JSON-Schema/regex constrained outputs; tool calling; video frame-rate/duration limits not stated. — [Perceptron docs quickstart](https://docs.perceptron.inc/); [Mk1.5 model card](https://docs.perceptron.inc/perceptron-mk1.5/models/perceptron-mk1.5)
- Funding: $21M round led by Bessemer Venture Partners reported alongside Isaac 0.5 (Aug 2026); co-founders Armen Aghajanyan and Akshat Shrivastava, ex-Meta FAIR. (Not a different "Perceptron" that raised $6.5M for a Web3 data network in Jul 2026.) — [TechCrunch, Aug 26 2026](https://techcrunch.com/2026/08/26/ex-meta-scientists-want-to-bring-visual-ai-to-the-factory-floor/); [Dealroom](https://dealroom.co/news/147114-ex-meta-scientists-raise-21m-to-bring-vision-ai-to-the-factory-floor/)

### Inferences
- For an **inventory-from-phone-video** use case in Oct 2025 with Isaac 0.1: a team would need to extract keyframes (e.g., 1 frame/sec), send each frame as an image, ask for pointed/localized item lists and counts, then de-duplicate items across frames themselves (no cross-frame tracking exists in Isaac 0.1). Isaac's documented strengths (grounded pointing, OCR of labels/price tags, counting, few-shot category learning from a couple of annotated example frames) fit shelf/pantry inventory well; its weaknesses for this task are no temporal identity, non-commercial weight license (fine for a hackathon demo, not for a product), and a small 2B model that trails Gemini 2.5 Flash on RealWorldQA/DocVQA.
- At hackathon scale, the fal.ai hosted endpoint ($0.26/$2.17 per M tokens) is the lowest-friction path; self-hosting via vLLM needs a GPU.
- Latency is unpublished for all Perceptron models; teams should benchmark on day one.

### Gaps
- No published numeric latency, rate limits, max image count per request, or image-token budget for Isaac 0.1.
- No official Perceptron statement on Isaac 0.1 video support (absence in model card/blog is the only evidence that it is image-only).
- Isaac 0.1's coordinate convention for points/boxes (normalized vs pixel) was not found in the fetched sources; it is presumably in the Perceptron SDK/user guide, which was not fetched.
- Isaac 0.2 (release date, changes) was not researched; it appears on perceptron.inc but no date was captured.
- Perceptron's own API pricing for Isaac 0.1 (vs fal's) and whether a hosted Perceptron API existed in Oct 2025 are unconfirmed; a third-party post claims Isaac model IDs were later retired (404 model_not_found) — single secondary source.

## Q6. Competing agentic-payments protocols (context): Mastercard Agent Pay, Google AP2, Stripe/OpenAI ACP, PayPal

### Takeaway
By mid-October 2025 four rival stacks existed: Mastercard Agent Pay (Apr 29, 2025; Agentic Tokens built on Mastercard tokenization, Microsoft Copilot integration), Google's open Agent Payments Protocol AP2 (Sep 16, 2025; signed Intent/Cart/Payment "mandates," 60+ partners incl. Mastercard, PayPal, Amex, Coinbase), the Stripe + OpenAI Agentic Commerce Protocol powering ChatGPT Instant Checkout (late Sep 2025; Shared Payment Tokens scoped to merchant and cart total, merchant keeps order control), and PayPal as an AP2/ACP participant. Visa's TAP explicitly positions itself as complementary to ACP and x402 rather than competing on checkout.

### Cited Findings
- **Mastercard Agent Pay** — announced Apr 29, 2025 as the launch of Mastercard's Agentic Payments Program; introduces Mastercard Agentic Tokens built on existing tokenization (contactless, card-on-file, Payment Passkeys); integrates Microsoft Azure OpenAI Service and Copilot Studio; example: agent completing a cross-border purchase with a virtual corporate card token. — [Mastercard newsroom](https://newsroom.mastercard.com/news/press/2025/april/mastercard-unveils-agent-pay-pioneering-agentic-payments-technology-to-power-commerce-in-the-age-of-ai); Mastercard is incorporating Cloudflare Web Bot Auth into Agent Pay (Oct 14, 2025). — [Cloudflare press release](https://www.cloudflare.com/press/press-releases/2025/cloudflare-collaborates-with-leading-payments-companies-to-secure-and-enable-agentic-commerce/)
- **Google AP2** — announced Sep 16, 2025; open, vendor-neutral, payment-method-agnostic; builds on A2A and MCP; 60+ launch partners including Mastercard, PayPal, Coinbase, American Express, Salesforce; "mandates" are tamper-proof, cryptographically signed digital contracts (Intent, Cart, Payment) covering real-time and delegated purchases. (Secondary coverage; Google's primary post not fetched.) — [TechGoondu](https://www.techgoondu.com/2025/09/18/google-cloud-unveils-open-protocol-to-enable-secure-payments-by-ai-agents); [Constellation Research](https://www.constellationr.com/index%2Ephp/insights/news/googles-agent-payments-protocol-fleshes-out-ai-agent-commerce)
- **Stripe/OpenAI ACP** — Stripe powers Instant Checkout in ChatGPT and released the Agentic Commerce Protocol, "a new, merchant-friendly open standard codeveloped by Stripe and OpenAI"; Stripe issues a Shared Payment Token scoped to a specific merchant and cart total so ChatGPT can start a payment without exposing credentials; merchant accepts/declines the order and uses its existing processor; initial scope US ChatGPT users buying from Etsy sellers, with 1M+ Shopify merchants slated next; launched the week after Google's AP2. — [Stripe newsroom](https://stripe.com/newsroom/news/stripe-openai-instant-checkout); [TravelDailyNews](https://www.traveldailynews.com/?p=434286)
- **PayPal** — named as an AP2 launch partner; reported to be building an ACP server (secondary sources). — [TechGoondu](https://www.techgoondu.com/2025/09/18/google-cloud-unveils-open-protocol-to-enable-secure-payments-by-ai-agents); [Crossmint comparison (secondary)](https://crossmint.com/learn/agentic-payments-protocols-compared)
- **Interop stance**: Visa TAP is "intended to work with the Agentic Commerce Protocol" and align with x402; Cloudflare contributed to AP2. — [Visa press release](https://investor.visa.com/news/news-details/2025/Visa-Introduces-Trusted-Agent-Protocol-An-Ecosystem-Led-Framework-for-AI-Commerce/default.aspx); [Cloudflare](https://www.cloudflare.com/press/press-releases/2025/cloudflare-collaborates-with-leading-payments-companies-to-secure-and-enable-agentic-commerce/)
- Later secondary claim [post-Oct-2025]: a Walmart test of ChatGPT Instant Checkout converted ~3x worse than sending shoppers to Walmart's own site, prompting OpenAI to shift toward merchant-owned checkout. — [Digital Transactions](https://www.digitaltransactions.net/openai-and-stripe-are-the-latest-fintechs-to-enable-agentic-commerce/) (single source, unverified)

### Inferences
- Layering as of Oct 2025: card networks (Visa VIC/TAP, Mastercard Agent Pay) handle agent identity + tokens + controls; AP2 standardizes user-intent mandates; ACP standardizes agent↔merchant checkout; Cloudflare Web Bot Auth is the shared agent-identity transport. A hackathon pitch can borrow AP2's "Intent Mandate → Cart Mandate" vocabulary while using Visa's TAP for agent verification — both are open specs with GitHub code.

### Gaps
- Google's and PayPal's primary announcements were not fetched; mandate internals (W3C Verifiable Credentials) come from third-party explainers only.
- Mastercard Agent Pay developer/sandbox availability as of Oct 2025 was not researched.
